## Section 2: Allocation Math / Formula Discussions

### Fee Formula — Confirmed by Admin

- **Formula:** `fee = (volume_pct / 100)^2 * budget`, where `volume_pct` is the integer percentage allocated (e.g., 20 for 20%).
- Admin hrvoje12345 confirmed (2026-04-29T16:32): "if you allocate 20% to something, 20 goes here."
- Simplified: `fee = 100 * x^2` where x is allocation in percent. (pixxel_phantom's notation.)
- Example from admin (2026-04-29T09:06): "invest 100k (10%) → fee = 10k. If goes up 20%: position = 120k, PnL = 120k - 100k - 10k = 10k. If goes up 0%: PnL = -10k."
- **Budget is a loan:** unused budget does not carry over; it "expires worthless."

### PnL Formula — Confirmed by Admin

```
PnL_product = (final_value - initial_investment - fee)
            = initial_investment * return_pct - fee
Final PnL = sum of PnL_product over all products
```

Budget spent is deducted (it's the cost basis); fees are an additional deduction on top.

### Fee-Optimal Allocation Math

- User aniemite_25697 (2026-04-29T07:50) posted an alternative formula: `PnL = budget × v × (r − v)` where v is fraction invested and r is return. This implies optimal `v = r/2` (differentiate and set to zero), i.e., allocate half the expected return as your budget fraction. For example, if you expect +20% return, optimal allocation = 10% of budget. **Community noted this is equivalent to the quadratic fee structure.**
- Multiple users computed that >25% single-product allocation becomes fee-prohibitive unless returns are large. User mothorax (2026-04-29T19:54): "if you invest 25%, even if it goes up 10%, doesn't the fee wipe out the profits?"
- Prior year fee formula shared for reference: `f(x) = 120 * x^2` (source: github.com/chrispyroberts/imc-prosperity-3) — slightly different coefficient than this year's `100 * x^2`.
- User weavedis (2026-04-30T00:01): "Not spending at all, 50/50 chance for each product so EV is negative with fees" — argues zero allocation if you have no signal.

## Section 5: Admin Clarifications / Mechanics

All from hrvoje12345 (admin) unless noted as tomas5880.

### Grading Mechanics (OFFICIAL)

1. **Return range + anchor:** IMC pre-defines a return range [x, y] and an anchor per product. The anchor reflects "how we imagined the story dynamics."
2. **Crowd correction:** Players' aggregate submissions shift realized returns within [x, y]. If most players submit buy, the return is closer to y. This is a *correction* mechanism, not the core driver. Explicitly described as "not as pronounced" as pure game-theory rounds.
3. **One trading day:** You read the news, submit allocations, one trading day happens, you receive PnL. No dynamic rehedging.
4. **Budget as loan:** Invest 100k → budget deducted; unused budget expires worthless. Fees are additional deduction. Final PnL = sum over products of (return_on_investment - fee).
5. **Fee formula (confirmed):** `fee = (volume_pct/100)^2 * budget`. If you allocate 20% of budget to a product, fee = (20/100)^2 * budget = 0.04 * budget = 40,000.
6. **Products are real goods (commodities) except Sulfur Reactor which is now a stock (equity).**
7. **Some news may already be priced in:** hrvoje12345 (2026-04-28T16:29): "New news. From the sentiment of the stories, some have been priced in from the past. You will see different time frames in different stories." And (2026-04-28T08:59): "You can assume that market has not seen this news when you see them (unless some are already priced in for some time)."
8. **Manual and algo are fully independent** (tomas5880, 2026-04-28T15:49): "Nope, manual and algo are fully independent!"
